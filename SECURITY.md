# Security Policy

## Supported versions

The project currently supports the latest development branch and the most recent published release line.

## Reporting a vulnerability

Please do not open a public GitHub issue for security vulnerabilities.

Report all security issues privately through the project maintainers using the repository security contact process. If a dedicated public security email is not yet established, use the private reporting channel defined by the Zerberus maintainers and keep the issue out of public GitHub discussion until a fix has been coordinated.

## Scope

This policy applies to the framework core, official adapters and official policy packs published under this repository.

## Response expectations

- Acknowledgement within a reasonable timeframe after private report;
- triage and severity assessment;
- coordinated remediation plan if applicable;
- public disclosure only after a patch and mitigation path are ready.

## Responsible disclosure

We ask reporters to:

- provide a clear description of the issue;
- include reproduction steps and impact where possible;
- avoid public disclosure before the maintainers can assess and address the issue;
- keep findings confidential while the fix is being developed.
